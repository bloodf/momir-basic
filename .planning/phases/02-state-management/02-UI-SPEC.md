# Phase 2 -- UI Design Contract

> Visual and interaction contract for the State Management phase. This is an infrastructure migration phase (Context -> Zustand, AsyncStorage -> MMKV, Scryfall polling -> NetInfo). The visual contract focuses on behavior preservation and the specific interaction changes that state migration introduces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Phase-Specific Interaction Contracts

### 1. No Flash of Empty State (MMKV synchronous hydration)

**Contract:** When the app launches, settings and history must appear instantly on the first render frame. There must be NO loading spinner, skeleton, or blank state while waiting for persistence to hydrate.

**Reason:** MMKV reads are synchronous. Zustand stores with `persist` middleware and MMKV-backed `createJSONStorage` hydrate during `create()`, before the first render. Unlike AsyncStorage (async), there is no gap between mount and data availability.

**Verification:** App launches to a fully populated home screen. Settings toggles reflect saved state. History list shows previously fetched cards. No intermediate loading state visible.

### 2. Responsive Layout on Rotation/Resize (ARCH-07)

**Contract:** All 5 call sites that currently use module-scope `Dimensions.get('window')` must update layout within the same render frame when the device rotates, folds, or resizes.

**Affected components:**
- `app/card.tsx` -- card detail layout
- `app/life-counter.tsx` -- life counter layout
- `app/print-preview.tsx` -- receipt preview layout
- `components/CardGridItem.tsx` -- card grid item sizing
- `components/HistorySheet.tsx` -- bottom sheet layout

**Implementation:** Replace `Dimensions.get('window')` with `useWindowDimensions()` hook inside component bodies. Move dimension-dependent styles from module-scope `StyleSheet.create()` to inline computed styles (useMemo-wrapped) within the component.

**Verification:** Rotate device 90 degrees. All affected screens update layout immediately without requiring back-navigation or re-mount. On foldable devices, layout adapts when screen size changes.

### 3. Network State Transition (ARCH-03)

**Contract:** Online/offline transitions are detected by the OS (NetInfo) within 1-2 seconds of actual connectivity change. API-specific reachability (Scryfall endpoint) is checked every 5 minutes on a periodic interval.

**Behavior:**
- NetInfo fires OS-level events instantly on connectivity change
- First 4 offline events on cold start are suppressed (false-offline protection)
- Offline toast appears only after suppression threshold is passed
- Online toast appears when connectivity is restored after being offline
- Periodic Scryfall health check confirms API reachability (catches captive portals)
- `isOnline` (boolean) reflects OS connectivity; `isReachable` (boolean) reflects API-specific reachability

### 4. Provider Tree Structure (ARCH-05)

**Before (7 levels):**
```
QueryClientProvider
  GestureHandlerRootView
    SafeAreaProvider
      SettingsProvider
        HistoryProvider
          NetworkProvider
            I18nProvider
              ToastProvider
                App
```

**After (4 levels):**
```
composeProviders([
  QueryClientProvider,
  GestureHandlerRootView,
  SafeAreaProvider,
  ToastProvider,
])
  App
```

**Contract:** Zustand stores (`useSettingsStore`, `useHistoryStore`, `useNetworkStore`, `useI18nStore`) are imported at module level. No provider wrappers for stores. Toast remains as a context provider because it manages UI rendering (Animated API), not data state.

### 5. Data Loss on Upgrade (D-08)

**Contract:** Users upgrading to this version will lose existing settings, card history, and locale preference. This is an explicit trade-off for simpler implementation (no AsyncStorage -> MMKV migration code).

**Mitigation:** The app should function normally with default settings on first launch after upgrade. Users can re-configure settings and re-fetch cards. This is a one-time loss.

**Documentation:** Release notes must mention: "This update includes a major state management upgrade. Your saved settings and card history will be reset to defaults."
