Steps:
1. Install: `bun add -D reassure@1.4.1`
2. Initialize: `npx reassure init` — this generates the `reassure-tests.sh` script, dangerfile, and `.reassure/` output directory. If the init command prompts for any configuration, accept defaults.
3. Verify `.reassure/` is added to `.gitignore` (the init command typically does this; if not, add it manually).
4. Update `jest.config.js` if needed: Reassure uses the `.perf-test.tsx` extension for its test files. Verify that `jest-expo` preset picks up this extension via `moduleFileExtensions` (it already includes `ts` and `tsx`, so `.perf-test.tsx` files should be matched). If Reassure init creates a separate `jest.reassure.config.js`, note it but do not merge — Reassure runs via its own CLI (`npx reassure`), not via the main Jest command.

DO NOT modify the existing Jest test configuration to include `__reassure__/` in the regular test path — Reassure has its own runner. The `.perf-test.tsx` files should NOT be picked up by `bun run test`.

<task type="auto">
  <name>Task 2: Create home screen cast flow Reassure baseline test</name>
  <files>__reassure__/home-cast.perf-test.tsx</files>
  <action>
Per D-08: Create a Reassure performance baseline test for the home screen cast flow — the core value interaction that must not regress during Phases 2-3.

Implementation:
1. Create `__reassure__/home-cast.perf-test.tsx`
2. Import `measureRenders` from `reassure`
3. Import `screen`, `fireEvent` from `@testing-library/react-native`
4. Import `HomeScreen` from `@/app/(tabs)/(home)/index`
5. Create a `ProvidersWrapper` component that wraps children with the minimum required provider tree:
   - `QueryClientProvider` (create a new `QueryClient` with `defaults: { queries: { retry: false } }` for test stability)
   - `SafeAreaProvider` (from `react-native-safe-area-context`)
   - `I18nProvider`, `SettingsProvider`, `HistoryProvider`, `NetworkProvider` (imported from providers/)
   - Mock `AsyncStorage` to return default settings and empty history (avoid real storage access)
   - Mock Scryfall API calls (use `jest.mock` or `msw` to return a fixed card response) — this is critical for stable measurements per RESEARCH.md Pitfall 5
6. Write two test cases:
   a. `test('Home screen initial render')` — measures baseline render of the home screen without interaction
   b. `test('Cast button press flow')` — measures render after pressing the cast button; use `fireEvent.press` on the cast button element, then `await screen.findByTestId('hero-art')` or similar to wait for the card display
7. Increase measurement runs for statistical stability: add `{ runs: 20 }` option to `measureRenders` (default is 10; cast flow involves async state so more runs reduce variance per RESEARCH.md Pitfall 5)

Mocking strategy (per RESEARCH.md Pitfall 5 — network requests cause high variance):
- Mock the Scryfall `fetchRandomCard` mutation to return a fixed `Card` object instantly
- This eliminates network latency variance from measurements
- The cast button press test measures React render performance, not network performance

If the HomeScreen component does not have a `testID` on the cast button, add one: `testID="cast-button"` on the primary cast/tap button element in `app/(tabs)/(home)/index.tsx`. This is a minimal, non-behavioral change.

After creating the test, run: `npx reassure --baseline` to establish the first baseline. Verify that `.reassure/baseline.json` is created with measurements.
