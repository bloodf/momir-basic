## Event Taxonomy

16 event types covering full printer lifecycle:
- Permission: REQUESTED, GRANTED, DENIED
- Discovery: STARTED, RESULT, COMPLETED
- Connect: STARTED, SUCCESS, FAILED, DISCONNECTED
- Job: QUEUED, DISPATCHED, COMPLETED, FAILED, SENT_UNKNOWN
- Native: ERROR

## Instrumentation Points

### Capability Service
- `requestAndroidBluetoothPermissions()` — emits permission events before/after Android permission flow
- `ensureBluetoothPermissions()` — emits granted/denied events based on permission state

### Registry Service
- `discoverPrinters()` — emits discovery start, per-device results, and completion
- `connectPrinter()` — emits connect start, success/failed with error codes
- `disconnectPrinter()` — emits disconnected event

### Queue Engine
- `processQueueForPrinter()` — emits job dispatched before dispatch call
- `recordTerminalState()` — emits completed/failed/sent_unknown based on outcome

## Diagnostic Capture Commands

Android:
```bash
adb logcat --pid=$(adb shell pidof host.exp.exponent) -s PrinterSession:*
```

iOS:
```bash
log stream --predicate 'subsystem == "com.rork.momir-basic.PrinterSession"' --level debug
```

## Certification Evidence

Logs include device/printer/build identifiers in JSON metadata:
- platform (android/ios)
- appVersion (semantic version)
- buildId (android versionCode / iOS buildNumber)
- timestamp (ISO 8601)
- event type and payload

This allows reproducible diagnostics tied to specific hardware certification runs.
