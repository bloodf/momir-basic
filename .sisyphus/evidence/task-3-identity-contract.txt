# Task 3: Transport Mapping and Printer Identity Contract

## Status: COMPLETE

## Changes Made

### 1. Added explicit transport enum with validation (`expo/types/index.ts`)
- Added `PrinterTransportType` enum with explicit values: BLE, CLASSIC, TCP
- Added `validateTransport()` function that throws on unknown transport (no BLE default)
- Added `CanonicalPrinterIdentity` interface for composite address+transport key

### 2. Fixed `mapNativeTypeToTransport` (`expo/services/printer/adapters/native.ts`)
- Changed default-from-unknown from `return 'ble'` to `return validateTransport(type)` which throws

### 3. Updated `PrinterPort` interface (`expo/services/printer/adapters/port.ts`)
- `connectPrinter(address: string)` - clarified parameter is address, not registry ID
- `disconnectPrinter()` - no parameter, disconnects current printer
- `isConnected(address: string)` - check by address

### 4. Fixed `AdapterWrapper` (`expo/services/printer/queue/engine.ts`)
- Now accepts `CanonicalPrinterIdentity` instead of registry ID
- Calls `connectPrinter(identity.address)` correctly

### 5. Fixed queue dispatch (`expo/services/printer/queue/engine.ts`)
- `dispatch()` now takes `CanonicalPrinterIdentity` parameter
- `processQueueForPrinter()` constructs identity from printer record and passes it

### 6. Updated fake adapter to match new interface (`expo/services/printer/adapters/fake.ts`)
- `disconnectPrinter()` takes no arguments
- `isConnected(address: string)` checks by address

### 7. Updated registry service (`expo/services/printer/registry/service.ts`)
- Calls `disconnectPrinter()` without arguments

## Key Findings

1. **Root cause of identity mismatch**: Queue's `AdapterWrapper` was passing registry UUID to `connectPrinter()` which expects address
2. **BLE default was hiding bugs**: Unknown transports silently defaulted to BLE instead of failing
3. **Canonical identity is address+transport**: Registry ID is for persistence only; adapter layer uses address+transport
