# Task 8: Queue Semantics Evidence

## Changes Made

### 1. New Explicit Job States (types/index.ts)
- `queued` - waiting to be processed
- `printing` - actively sending to printer (replaces dispatching)
- `printed_confirmed` - successfully printed and confirmed (replaces completed)
- `failed_retryable` - failed, auto-retryable after backoff (replaces retry_wait)
- `failed_terminal` - failed, non-retryable operator must investigate (replaces failed_manual)
- `sent_unknown` - uncertain delivery disconnect mid-write, operator reconciliation required (NEW)

### 2. Canonical Printer Identity for Safe Resume
- Added `canonicalIdentity?: CanonicalPrinterIdentity` to `PrintJob` interface
- Stores address+transport snapshot at job creation
- Enables safe resume after app restarts by verifying printer at same canonical identity

### 3. Queue Engine Redesign (queue/engine.ts)

#### Failure Type Classification
- `pre_write` - render or connect error, retryable
- `uncertain_write` - disconnect mid-write, maps to sent_unknown (NOT retryable)
- `terminal` - non-retryable hardware error

#### Key Behavior Changes
- `sent_unknown` state requires explicit operator action (retry or abandon)
- No auto-retry for `sent_unknown` - prevents duplicate silent printing
- `failed_terminal` after max retries exceeded
- Retry backoff tied to canonical identity, not registry ID

#### New Functions
- `abandonJob()` - marks job as failed_terminal
- `getQueueSummary()` - returns counts including sent_unknown and failedTerminal
- `resumeQueueAfterRestart()` - verifies printer connectivity before resuming

### 4. Repository Updates (storage/repositories.ts)
- `createJob()` now accepts optional `canonicalIdentity`
- `getPrinterByCanonicalIdentity()` - lookup printer by address+transport
- `getJobsRequiringReconciliation()` - queries all sent_unknown jobs
- `rowToPrintJob()` parses canonical_identity JSON

### 5. SettingsProvider Fix (SettingsProvider.tsx)
- Removed stale `printerConnected` check from app restart handler
- Now uses `resumeQueueAfterRestart()` which:
  - Verifies actual printer connectivity before resuming
  - Blocks resume if sent_unknown or failed_terminal jobs exist
  - Only resumes queued/failed_retryable jobs safely

## State Transition Diagram

```
queued ──dispatch──> printing ──success──> printed_confirmed
                    │
                    └──failure/pre_write──> failed_retryable (with backoff)
                    │                         │
                    │                         └── max retries exceeded
                    │                              │
                    └──failure/uncertain_write────> sent_unknown (operator action)
                    │                              │
                    └──failure/terminal───────────> failed_terminal
```

## Safe Resume Logic

On app restart:
1. Check if printer is still connected (via isConnected with canonical address)
2. If yes, check for sent_unknown or failed_terminal jobs
3. If any exist, DO NOT auto-resume - operator must reconcile
4. If none exist, safely resume queued/failed_retryable jobs

## Transport-Aware Retry

Retries are tied to `{address, transport}` canonical identity:
- Same printer can be reached via different transports
- Registry ID alone insufficient for retry routing
- Canonical identity stored at job creation for safe resume

## Duplicate Print Prevention

- sent_unknown jobs require explicit operator retry
- No silent auto-retry on uncertain delivery
- Resume requires positive verification of printer connectivity
